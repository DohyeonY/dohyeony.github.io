## 오늘 한 일

### 1. 보스 노드 생성 (Area2D)
빨간 네모 보스를 `Area2D`로 만들었다. 패링 판정(영역 감지)을 위해 `CharacterBody2D`가 아닌 `Area2D`를 선택.

구조:

```
Battle
 ├ Player        (파란 네모, CharacterBody2D)
 ├ Ground        (땅, StaticBody2D)
 └ Boss          (빨간 네모, Area2D)
    ├ CollisionShape2D   (RectangleShape2D 80x120)
    └ ColorRect          (빨강 80x120)
```

- 보스 크기 80x120 → 주인공(40)의 약 2~3배. "패링 게임은 보스를 크게" 원칙대로.
- 위치: x 400, y 180 (플레이어 오른쪽, 땅 위)

### 2. 보스 공격 사이클 (예고 → 공격)
패링 게임 보스의 기본 골격인 **상태 사이클**을 구현했다. 스프라이트가 아직 없어서 색 변화로 상태를 표시.

```
[대기] → [예고] → [공격] → [후딜] → 다시 대기
 빨강     노랑     흰색      빨강
                   ↑ 이 순간 패링 입력 → 성공 (다음 단계에서 구현)
```

- **IDLE(대기)**: 빨강, 1.5초
- **TELEGRAPH(예고)**: 노랑, 0.7초 — "곧 공격한다"는 단서
- **ATTACK(공격)**: 흰색 번쩍, 0.2초 — 실제 타격 순간
- **RECOVERY(후딜)**: 빨강, 0.8초

`enum`으로 상태를 정의하고 `_process`에서 타이머를 돌려 상태 전환하는 방식.
보스가 혼자 리듬을 타는 것까지 구현 완료. 패링 판정은 다음 단계.

## 막힌 것 / 에러

### 들여쓰기 에러 (Tab vs Space)

```
used tab character for indentation instead of space as used before
```

**원인**: GDScript는 들여쓰기로 코드 블록을 구분하는데, 코드를 붙여넣을 때
탭(Tab)과 스페이스(공백)가 섞여서 발생. GDScript는 둘을 섞으면 에러가 난다.

**해결 시도**:
- `Edit → Convert Indent to Tabs` 메뉴로 통일하려 했으나, Godot 4.6에서는
  해당 메뉴 항목이 바로 안 보임 (위치/이름이 다른 듯).
- 대안: 에러 난 줄의 들여쓰기를 직접 지우고 Tab 키로 다시 입력하거나,
  Editor Settings → Text Editor → Behavior → Indent 에서 Type을 Tabs로 통일.

> **다음에 기억할 것**: Godot는 기본 들여쓰기가 **탭**이다.
> 코드 붙여넣은 뒤에는 들여쓰기를 탭으로 통일하는 습관을 들이자.

## 배운 것

- 패링 보스의 핵심은 **"예고(텔레그래프) → 공격"** 리듬. 예고가 있어야
  플레이어가 패링을 준비할 수 있고, 그게 "읽고 대응하는" 재미를 만든다.
- 보스를 크게 만드는 이유 = 모션 가독성. 작으면 예고 동작이 안 보여서
  난이도만 오르고 재미는 죽는다.
- `Area2D`는 "영역 감지"용이라 패링 판정에 적합.
